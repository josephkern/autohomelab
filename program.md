# program.md — the autohomelab research agenda

Durable, human-maintained agenda for the autonomous tuning agent, mirrored on
[karpathy/autoresearch](https://github.com/karpathy/autoresearch) and on the prior
`homelab-tooling` loop. The agent reads this file and the current runbook, proposes one change,
benchmarks it, and keeps or discards by the metric. Substitution from autoresearch: **maximize
tok/s** instead of minimize `val_bpb`.

## Setup

- Target one `(node, model)` pair. Node = fingerprint from `scripts/probe.sh`
  (`results/<node_fp>/node_profile.json`); model = HF id + pinned revision.
- Agree a **run tag** (e.g. `20260613`) and work on a branch `autoresearch/<tag>` off `main`.
- **First run is always the baseline**: `runbooks/<org>/<model>/baseline.sh` as-is (generated by
  `scripts/gen_baseline.py`).
- Confirm **N** (benchmark repeats per config); default **N=3**, take the **median** tok/s. Do
  not change N mid-run — it moves the variance floor and invalidates cross-iteration comparison.
  (Lesson from `homelab-tooling`: single-sample scoring chases noise, not signal.)

## What you may change

The **entire runbook `.sh`** for the current `(node, model)` — it is the complete reproducible
unit: pinned image + model + serving flags. Everything else is locked (probe, bench harness,
model weights).

Tunable dimensions:
- **Serving flags**: `max-num-seqs`, `max-num-batched-tokens`, `gpu-memory-utilization`,
  `kv-cache-dtype`, chunked prefill, prefix caching, `async-scheduling`, `max-model-len`,
  attention/moe backend, cudagraph capture sizes, speculative config.
- **The image version itself** (`VLLM_IMAGE`): a real dimension — a newer pinned image can change
  available kernels/backends. Pin any new image by digest in `backends/vllm/image.lock` first.

**All else equal, simpler is better.** A change must earn its complexity with a real tok/s gain.
The model, request distribution, and the GuideLLM sweep are the controlled variables.

## The experiment loop

1. Read `program.md` and the current best runbook.
2. Decide **one** change. Copy the current best to `<YYYYMMDD>_<change>_tuned.sh` and edit it.
   Document the **delta** in the file header (e.g. "Deltas vs baseline: `--max-num-seqs 4 → 32`,
   `+ --max-num-batched-tokens 8192`") — this is the autoresearch journal, inline.
3. `git commit` the new runbook (one change per commit, so the result is attributable).
4. `scripts/serve.sh <that .sh>` → health → (on unified nodes: `sync && echo 3 | sudo tee
   /proc/sys/vm/drop_caches` to stop fs-cache starving CUDA) → `scripts/bench.sh <that .sh>` ×N;
   take median.
5. Append the `results.tsv` row(s) and a narrative line to `logbook.md`.
6. Keep (advance the best pointer) if median tok/s improved beyond noise; else discard. Either
   way **continue — do not pause to ask whether to continue.**

## Output & logging

Each run writes a raw GuideLLM bundle to `results/<node_fp>/<org>/<model>/data/<run_id>/` and a
`results.tsv` row (see AGENTS.md for the schema). `status` ∈ `keep`/`discard`/`crash`. Then one
narrative line in `logbook.md`: what changed, the effect, and the call.

## Reproducibility (non-negotiable)

- Image pinned by `sha256:` digest in the runbook; tooling pinned via `uv.lock`.
- `logbook.md` opens each session with the environment block (driver, firmware, CUDA, image
  digest, vLLM version, GuideLLM version, model revision) — see docs/reproducibility.md.
- Before pulling/running any image, inventory local docker images/containers first.
